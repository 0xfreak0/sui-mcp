## What the tools do

<CardGrid>
	<Card title="Tracing funds">
		`trace_funds` follows one path forward or backward, and `trace_flow_graph` traces priced coin flows and valued object handovers across branches. Unvalued object movements remain separate. `resolve_bridge_transfer` reports cross-chain transfer identifiers and destinations where available. `find_funding_sources` reads first funding for multiple addresses; `build_wallet_edges` reports evidence for possible shared operation.

		[Incident investigation tools](/reference/tools/incident-investigation/)
	</Card>
	<Card title="Attack and exploit analysis">
		`analyze_attack_tx` reports a transaction's per-address coin and USD net, flash-loan legs, swaps and pool losses. `summarize_incident_losses` totals a window of transactions with historical pricing coverage. With `PYTH_API_KEY`, `compare_oracle_price` compares Pyth prices with DeepBook trades; without the key it reports `oracle_unavailable` and makes no comparison.

		[Incident investigation tools](/reference/tools/incident-investigation/)
	</Card>
	<Card title="Package and capability audits">
		`analyze_package` summarizes a package's API with a heuristic risk scan and a capability audit, without an external binary. `get_upgrade_history` shows who published each version and who held the UpgradeCap. `diff_package_upgrade` shows what an upgrade changed.

		[Package tools](/reference/tools/packages/)
	</Card>
	<Card title="Wallet and token profiles">
		`identify_address` classifies an address as a wallet, package, validator or object. `get_wallet_overview` lists balances and recent transactions. `analyze_token` reports metadata, price, supply, sampled holders on bounded scans and a complete ranking only when both holder walks finish. `find_pools` searches current pools on supported venues and reports per-venue coverage.

		[Recommended starting points](/reference/tools/starting-points/) · [Pool discovery](/reference/tools/defi/#find_pools)
	</Card>
	<Card title="Everyday prompts">
		`what_happened_to_my_funds`, `who_controls_this_token`, `who_controls_this_protocol` and `who_is_this_wallet` answer common questions. Each gives a short plain answer first, then a `How sure` line, then the digests and addresses behind it.

		[Prompts](/reference/prompts/)
	</Card>
</CardGrid>

## Install

<CurrentRelease />

Add this to your MCP client config (Claude Code, Claude Desktop, Cursor, or anything else that speaks MCP over stdio):

```json
{
  "mcpServers": {
    "sui": {
      "command": "npx",
      "args": ["-y", "sui-analytics-mcp"]
    }
  }
}
```

No account, API key or config file is required for public chain reads. The server defaults to mainnet and requires Node.js >= 22.13. An optional local store records labels, findings and watch cursors; see [Configuration](/guides/configuration/).

For investigative work, start with the forensics tools loaded:

```json
"env": { "SUI_TOOLS": "core,forensics" }
```
